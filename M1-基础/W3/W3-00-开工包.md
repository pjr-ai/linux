## 卡 2 · DNS 类【故障实验 · 手册】
**场景**：能 ping 通 IP、却 ping 不通域名——"是网络不通，还是名字没解析出来？"
**造（先 `cp /etc/resolv.conf /tmp/resolv.bak` 保命；网络类实验前打快照）**：
1. 先 `nslookup www.baidu.com`（或你能通的域名）——**把解析到的 IP 记下来**
2. 把 `/etc/resolv.conf` 的 DNS 改成不存在的地址（如 `1.2.3.4`）
3. 复现：`curl www.baidu.com` 失败；`ping <刚记的IP>` 仍然通 → 问题缩到"名字解析"层
4. 定位：`nslookup` 看它现在解析成什么／报什么错
5. 修回（改回原内容）→ 复验 `curl` 成功
- **彩蛋（可选）**：在 `/etc/hosts` 里把某域名指到错 IP → 体会 hosts 的优先级＋怎么查（`getent hosts`）
**弹药**：`cat /etc/resolv.conf` · `nslookup` · `dig` · `ping` · `curl -v` · `cat /etc/hosts` · `getent hosts`
**学习源**：《Linux网络基础.md》DNS 那节
**预算**：2.5–3h

## 卡 3 · 握手与连通排查【手册】
**场景**：服务"到底通不通"——三种答案长得不一样：**通** / **Connection refused**（有人立刻拒绝：没服务听／明确 REJECT）/ **超时无响应**（被丢：DROP／路由黑洞——"卡住"和"被拒"是两回事）。
**造**：
1. **没服务**：`nc -zv 127.0.0.1 9999`（没装 nc 就 `curl -v telnet://127.0.0.1:9999`）→ 看 refused
2. **正常**：8080 起 http.server → `curl -v` / `telnet` / `nc -zv` 各连一次，记下三份输出的差别
3. **被挡（可选·看环境）**：firewalld 在跑的话，把某端口放行撤掉再从 Windows 侧连——大概率"卡住/超时"；没跑就跳过，记一句：**timeout＝被丢，多半防火墙 DROP**
- **加餐**：`ss -tan` 找找 TIME_WAIT 长什么样；查一下 CLOSE_WAIT 是什么、讲一句（你笔记里出现过）；**彩蛋**：装了 tcpdump 就 `tcpdump -nn -i any tcp port 8080 -c 10` 边连边看 **SYN / SYN-ACK / ACK**
**弹药**：`curl -v` · `telnet` · `nc -zv` · `ss -tan` / `ss -s` · `firewall-cmd` · `tcpdump`（彩蛋）
**预算**：3h
