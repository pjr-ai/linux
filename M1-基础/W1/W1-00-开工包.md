## 一、为什么用"造事故"来学

- 运维面试问得最多的不是"会不会背"，是"讲一次你排障的经历"；JD 里"故障排查"出现 19 次——市场直接点名这个能力。
- "先系统学完再做"是弯路：光看不练，两周后剩不了多少（你有前科：课程笔记"部分见"）。
- 正确顺序是反的：**先学 30 分钟够用的 → 动手把不会的逼出来 → 写进手册**。六周之后，手册摞起来，就是你的"系统"。

## 二、通用流程（每篇都走这 5 步）

1. **学（30–60 分钟）**：照每篇的《弹药清单》把命令认一遍（man / 课程 / 你旧答卷）。不要求记住——知道"箱子里有这把刀"即可。
2. **造（约 10 分钟）**：亲手把机器弄坏。规矩：**先想好怎么恢复再动手；动配置文件前先备份（cp xx.conf xx.conf.bak）；不放心先打快照。** 虚拟机是安全沙盒，放心折腾。
3. **修（1–2 小时）**：从现象出发定位→修复。**每条命令和输出都留着**——它们是手册的原料。
4. **验（10 分钟）**：证明真修好了（服务能跑 / 资源回落 / 不再报错）。无验证＝没修好。
5. **写（30–40 分钟）**：按四段模板落成手册。

**卡住规则**：同一个点卡 30 分钟 → 一句话发我：「试过 A、B，卡在 C」。我给提示，不给答案。

## 三、手册四段模板

```
# W1-0X-主题
## 现象 —— 我看到的坏情况（原始输出/截图贴进来）
## 定位 —— 怎么一步步缩小范围（每条命令＋输出，写清"为什么用这一步"）
## 根因 —— 到底什么坏了（争取一句话说清）
## 复盘 —— 下次遇同类怎么更快（≥3 行，要具体到命令）
> 自评：独立 / 查资料（列出哪些） / 卡住（卡在哪、后来怎么解决）
```

## 四、三篇场景卡（按"由熟到生"排序）

### 篇 1 · 日志类【先做】
- 场景：制造 5 次失败登录（ssh 输错密码/用户名即可），然后以"有人在爆破吗"的视角排查：几次？什么时候？从哪来？
- 弹药清单：`grep -c / -i` · `tail -f` · `head` · `wc -l` · `less` · 日志在哪（/var/log/secure、/var/log/messages）· 按时间筛（如 grep "Sep 15"）
- 学习源：10 题批改单里的 Q5/Q6（在 `M0-定位\`）+ `man grep`
- 交：手册 1 篇 ｜ 预算 2.5–3.5h

### 篇 2 · 资源类
- 场景：让 CPU 飙起来（提示：一个死循环就行）→ 找出来 → 送走 → 验证回落。
- 弹药清单：`top`（交互用法：排序 / 找列 / 杀进程 / 退出）· `ps aux --sort=-%cpu` · `kill` 的信号（默认哪个？-9 什么时候用？）· 验证进程已死的命令
- 学习源：你的 Q9 记录（`--sort` 的教训就在那）+ `man top`
- 备选：把 9.10 磁盘实验（`学习笔记\磁盘撑爆排障记录实验`）按本格式升级重写
- 交：手册 1 篇（含处理前后对比）｜ 预算 3–4h

### 篇 3 · 服务类【最后做·最新】
- 场景：把一个服务弄得起不来（三选一：配置改错一行 / 监听端口改成"已被占用"的 / 强行 kill 造成残留），定位→修复→能启动。
- 弹药清单：`systemctl status / is-active / start / stop / enable` · `journalctl -u 服务名 / -xe` · `ss -lntp`（谁占着端口）· 配置备份习惯 · `vi` 最小操作（i / Esc / :wq）
- 学习源：你的 Q8 记录 + `man systemctl`
- 交：手册 1 篇（根因一句话能说清）｜ 预算 3–4h
