## 一、W1-01 日志排查（/var/log/secure · 登录失败）

**主线**：查日志 = 先「数出量级」，再逐步「缩小维度」：次数 → 时间 → 来源 → 结论。

**原理补强**
- 查日志的手艺就两件事：**过滤**（grep 家族）＋**汇总**（sort / uniq），你的三步就是这两件事的组合。
- **LC_ALL=C 那坑的通用版（＝封箱追问的「基准」）**：日志里写的是 `Sep 13`，你本机 `date` 在中文环境输出「9月 13」——**查询要对齐“数据源里实际长什么样”，不是对着你眼前的环境想当然**。通杀习惯：查日志 / 改配置 / 对齐格式前，先 `head` 几行看清原始格式，再动手写命令。
- `grep` 参数诀：`-i` 忽略大小写 ｜ `-c` 只数行数 ｜ `-F` 纯字符串匹配（不当正则解析） ｜ `-o` 只吐出匹配到的那一小段 ｜ `-E` 扩展正则（`{ } ( )` 不用逐个转义）。
- 汇总金句：`... | sort | uniq -c | sort -nr` = 「排序 → 去重计数 → 按次数倒排」。查 IP、查错误类型、查来源，全用它收尾。

**面试追问（答点）**
1. 「怎么判断服务器有没有被暴力破解？」→ 数失败（`grep -ci`）＋ 来源分布（汇总套路）＋ 时间是否集中；系统自带 `lastb`（专列失败登录）、`last`（成功登录）——报出这俩是加分项。
2. 「`/var/log/secure` 是 RHEL 系的；Ubuntu 呢？」→ `auth.log`；再进一层：`journalctl -u sshd` 也能查（日志被 systemd-journald 统一收了口）。
3. 「日志越写越大怎么办？」→ `logrotate`（轮转 / 压缩 / 淘汰）——词先认下，M2 动手。

**易错/拓展**
- 忘 `-i` 大小写对不上 = “查了个寂寞”；管道每一步都先想“这一步把数据缩小到哪”。
- 你写的结论三件套（11 次 · 16:12 前后 · 192.168.230.1）= 安全日报的标准格式。
- 复盘里那条「写个脚本排查这个」【待 M1 后段兑现】——账记着，脚本周一起兑现。

## 二、W1-02 资源类（CPU 死循环）

**主线**：谁在吃（top）→ 吃的是谁（PID）→ 处置（kill）→ 复验（top 回落）。

**原理补强**
- `top` 头部先会读：`load average: 1/5/15 分钟` = 系统压力值（粗判：接近核数 = 忙，超过 = 排队）；`%Cpu(s)`：`us` = 用户态（你的死循环就在这）/ `sy` = 内核态 / `id` = 空闲 / `wa` = 等 I/O。
- `kill` 发的是**信号**：`-15`（TERM，默认）= 请它体面退出；`-9`（KILL）= 强杀、不给机会善后。规矩：**先 15，等几秒不退再 9**——模拟场景直接 9 可以，生产里 9 可能丢数据。
- `kill` 吃的是 **PID**；按名字杀要用 `pkill` / `killall`（有同名误杀风险，慎用）。
- 复验 = 闭环（你已养成，保持）：处置完必须回头看证据。

**面试追问（答点）**
1. 「CPU 100% 怎么排查？」→ `top`（按 P 排行）定位 → 是不是业务进程 → 不是：报备后处置；是：往里挖（`top -H` 看线程）→ 处置 ＋ 复验。
2. 「load 高但 CPU 不高？」→ 在等 I/O：看 `wa`、`iostat`；进程堆在 D 状态（不可中断睡眠）也会顶 load。
3. 「`kill -9` 杀不掉是怎么回事？」→ 进程卡在内核态（D 状态），信号挂着——等 I/O 返回或重启；面试喜欢拿这题挖“为什么杀不掉”。

**易错/拓展**
- 抄 PID 前先 `ps -p <PID> -o pid,user,cmd` 看一眼身份，别杀错人。
- 顺手兄弟：`ps aux --sort=-%cpu | head`、`uptime`、`pgrep`；客气级手段：`nice` / `renice` 降速不杀。

## 三、W1-03 服务类（配置改坏 → 起不来）

**主线**：六步闭环——看现状 → 看日志 → 修 → 自检 → 重启 → 复验。

**原理补强**
- 两把“探照灯”分工：`systemctl status` = 现状（active/failed、退出码、日志尾巴）；`journalctl -u 服务名` = 全量历史（`-f` 追、`--since` 限时段、`-n 50` 看尾）。`-x` = 附解释性提示，排障期开着不亏。
- **先自检再重启**：应用自带“配置语法检查”（你的 mysvc 是 `--check`；nginx 是 `nginx -t`、sshd 是 `sshd -t`）——自检过了再重启，避免“改了 → 重启 → 又挂”循环。真实口径：**改配置三件套 = 备份、自检、再生效**（自评里你已经悟到一半）。
- `sed -i` 的 `-i` = 原地改文件（不可撤销）——所以 `cp config config.bak` 先手：这是纪律，不是礼貌。
- `command -v python3` = 确认“这命令指向哪个可执行文件”，排除跑错解释器。

**面试追问（答点）**
1. 「服务起不来，排查顺序？」→ `status` 看状态 → `journalctl -u` 看日志 → 高频四类：配置错 / 端口被占（`ss -lntp`）/ 权限（属主·x 位）/ 依赖没起。你这次是第一类（一个字母）。
2. 「`restart` 和 `reload` 区别？」→ restart = 停再起（会断服务）；reload = 不重启进程、重读配置（优雅，需服务支持，如 nginx）。
3. 「`enable` 和 `start` 区别？」→ start = 现在起；enable = 开机自启；新装服务标准动作 = 两个都做（双保险）。

**易错/拓展**
- 改了 systemd 的 unit 文件要 `daemon-reload`；改应用自己的配置（你这次）不用——别混。
- 复验三眼：`status` ＋ 应用自检 ＋ 端口/接口再探（`ss -lntp`）。
- 关联预告：端口占用排查 = `ss -lntp | grep :端口`——W2 网络类马上撞上它。
