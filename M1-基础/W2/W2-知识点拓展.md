## 一、W2-01 磁盘类（删了文件，空间不还）

**主线**：`rm` 只是把「名字」摘掉；数据块要等**最后一个拿住它的人松手**才回收。

**原理补强**
- Linux 文件 = inode（元数据）＋ 数据块；文件名只是目录里“指向 inode 的一条记录”。`rm` = 把这条记录去掉。
- 若有进程正打开着它（你 `tail -f` 挂住的那只手），内核里“还有人引用”的状态还在 → **数据块不回收 → `df` 不降**。
- 为什么 `du` 找不到：`du` 是**按名字遍历目录树**统计的，文件没名字它就看不见——`df` 和 `du` 对不上时，先想“有没有无名文件”。（对复盘里一句话的修正：`du` 不是“查有没有被删”，是“按名字统计大小”。）
- `lsof +L1` 的来历：`+L1` = 列出「链接数小于 1」（名字已没、文件还开着）的条目——它就是“揪无名文件”的专用探照灯。
- 你 `kill` 掉进程后 `df` 回落 = 引用清零、块回收，闭环完整。

**面试追问（答点）**
1. 「df 和 du 结果对不上，还有哪些原因？」→ ① 已删未释放（本例）② 权限不够统计不全 ③ 挂载点被覆盖 ④ 稀疏文件 / 保留块。
2. 「不杀进程能救吗？」→ 首选让服务重启 / 重载；应急可 `> /proc/<PID>/fd/<N>` 清空那个句柄（了解即可，别当日常操作）。
3. 「现实里最常见在哪种场景？」→ **日志文件**：被 logrotate 删了但服务没重开、句柄还挂着——所以轮转后常配套 `reload`。预防 = 轮转策略 ＋ `df` 监控 ＋ 事后复查。

**易错/拓展**
- `fallocate` 秒建文件（只占块、不算数）；`dd` 逐块写（慢但“真”）；`truncate -s 0 文件` = 清空内容不删名字。
- inode 也会被用完：`df -i` 一排 100% 照样报“空间不足”（9.10 实验里你见过）。
- 「盘满先删谁」：`du -h --max-depth=1 / | sort -h` 从大往小找，比挨个目录点开快。

## 二、W2-02 权限类（permission denied）

**主线**：被拒时回答两个问题——**以谁的身份？卡在路径的哪一环？**

**原理补强**
- 文件与目录，rwx 含义不同：
  - 文件：`r` 读内容 / `w` 改内容 / `x` 执行。
  - 目录：`r` 列名字 / `w` 建删改名 / `x` **进入与穿过**。
- 所以你那次“目录 644”：`r` 在 → `ls` 看得到名字；`x` 没了 → `cd` 进不去、里面的文件够不着。**要够到任何文件，路径上每一级目录都要有 x**——“明明文件权限没问题怎么还是被拒”的常客。
- 八进制 = 三个位相加：`r4 w2 x1`；`644` = rw-/r--/r--，`755` = rwxr-xr-x。默认值多半来自 `umask`（root 常见 022 → 文件 644 / 目录 755）。
- `su - tester` 的 `-` = 登录式切换（带上对方环境）；落手前 `whoami` / `id` 确认“我是谁、在哪个组”。
- root 的“特权”边界：基本无视读写检查，但**执行文件仍要求至少一个 x 位**（脚本场景会撞上，知道有这事）。

**面试追问（答点）**
1. 「644 / 755 数字含义？」→ 逐位拆着讲（4+2+1），顺手把 umask 说出来。
2. 「怎么给团队共享一个目录？」→ 组归属 ＋ 组权限 chmod；进阶层：SGID（新文件继承组）、ACL（`setfacl`）——词先认识。
3. 「一律 777 行不行？」→ 不行：任何人可写 = 可被塞脚本；最小权限原则，按需给。

**易错/拓展**
- `-R` 递归误伤（旧坑）：递归前先 `ls` 看清范围、想清后果。
- 排障小神器 `namei -l /路径`：一次把路径上每级目录的权限序列出来——“卡在哪一环”一屏看清。
- `stat 文件` 看属主 / 权限 / 时间全貌；`ls -l` 的第一列、第三四列先会读。

## 三、W2-03 定时任务类（cron 不执行）

**主线**：cron 跑脚本的环境，**不是你的 shell 环境**——“终端能跑”不保证“cron 能跑”。

**原理补强**
- cron 执行时环境极简：PATH 只有 `/usr/bin:/bin` 这类基础目录（**没有 /usr/sbin**）、不读 `~/.bashrc`、不带你终端的变量 → `/usr/sbin` 下的命令（`ss`、`ip`）找不到就**静默失败**。
- 脚本两条调用路径的差别（故障 B 的谜底）：crontab 里直呼 `/opt/x.sh` → 要 `x` 权限；写 `bash /opt/x.sh` → 由 bash 去读它，不需要 `x` 位。
- 排查顺序（你亲手跑出来的那条）：服务（`systemctl status crond`）→ **是否被调起**（`/var/log/cron` 里有没有 CROND 点名）→ 执行环节（权限 → PATH → 工作目录 → 输出报错）。
- “静默失败”的解法 = 把输出收出来：`命令 >> /tmp/x.log 2>&1`（`2>&1` = 错误流并进标准流一起落文件）。cron 本来会把输出“邮寄”给用户，但机器常没配邮件 → 看着像什么都没发生。
- 时间字段五格：`分 时 日 月 周`（`* * * * *` = 每分钟）。

**面试追问（答点）**
1. 「cron 任务没执行，怎么排查？」→ 背你那条顺序线：服务在不在 → 有没有被调起（日志）→ 权限 / PATH / 环境 → 输出重定向抓报错。这题你有“亲手做过”的版本，讲时带细节。
2. 「为什么要写绝对路径？」→ PATH 极简 ＋ 工作目录不确定，双保险。
3. 「系统级定时还有什么？」→ `/etc/crontab`、`/etc/cron.d/`、`/etc/cron.daily`（anacron 兜底）；再往上 = systemd timer（知道词）。

**易错/拓展**
- `crontab -r` = **清光一切**（没有确认、没有回收站）；删单条用 `-e`。动手前 `crontab -l > /tmp/cron.bak`。
- 每分钟的测试任务用完就停——今天“清场”就是练这个。
- 两个“知道即可”：cron 命令里的 `%` 要转义（`\%`）；“日 / 月”和“周”字段有互斥组合规则。

## 四、W2-04 网络类（本机通、外面不通）

**主线**：先问“**服务把门开给谁**”（绑定地址），再问“门口有没有拦”（防火墙）。

**原理补强**
- 监听地址三种：
  - `127.0.0.1:8080` = 只接本机的客（回环地址，别的机器到不了）；
  - `0.0.0.0:8080` = 本机**所有地址**都接（哪张网卡来都行）；
  - `192.168.x.x:8080` = 只接那张网卡的客。
- root cause 那句更准的说法：不是“进程的 IP 被改了”，而是“**进程监听的绑定地址选成了 127.0.0.1**”——服务把门开向了内部。
- `ss -lntp` 读法：`-l` 只听着的 / `-n` 不解析名字（快） / `-t` 只看 TCP / `-p` 带进程。Local Address:Port 列 = “门开在哪”；users 列给 PID。
- 分层找茬链：**网络通不通（ping）→ 端口有没有人听（ss）→ 听给谁（绑定地址）→ 门口拦不拦（firewall-cmd）→ 更底层（SELinux `getenforce`，CentOS 常见）**。

**面试追问（答点）**
1. 「服务本机能连、别的机器连不上，怎么查？」→ 就背分层链：ss 看绑定 → 防火墙 → SELinux →（云主机再加：安全组）。
2. 「`0.0.0.0` 是什么？」→ “所有本地地址”的通配绑定；不是某个真实 IP。
3. 「怎么只对内网开放？」→ 绑内网 IP；或绑 0.0.0.0 ＋ 防火墙只放行内网段（生产常见后者）。

**易错/拓展**
- 改网络类配置 = **可能掐断 SSH**：动前打快照；真断了走 VMware 控制台。
- `firewall-cmd --permanent` 加规则后要 `--reload` 才生效；临时规则重启即没——两层别混。
- 端口被占：`ss -lntp | grep :8080` → 换端口或处置占坑进程；kill 后端口释放可能有几秒 TIME_WAIT（正常现象）。
