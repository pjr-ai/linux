我在 Windows 上故意输错密码，模拟被爆破，然后以"有人在爆破吗"的视角查日志。定位分三步：先定量级，grep -ci 数 Failed password，总共 11 次；再查时间，grep 月份一开始搜不到，因为中文环境 date 出的是"9月"，日志里写的是 Sep，加 LC_ALL=C 才对得上；最后提来源，grep -oE 只把 IP 抠出来，再用 sort | uniq -c 聚合，锁定 192.168.230.1。根因：不是入侵，是我自己的自测，直接原因是密码错误。教训两条：先定量级再展开维度；命令搜不到，先怀疑 locale 和格式不匹配。

现象是 CPU 被打满。定位就三步：top 进去按 P 以 CPU 排行，找出占用的 PID；kill -9 杀掉；再 top 确认 CPU 回落。根因是我在另一个 SSH 会话里跑了一个死循环——while :; do :; done，纯忙等，把一个核占满。复盘也是三句：top 掉，kill -9 收，top 验。教训有两条：死循环一定要加 timeout，或者用 taskset 钉在单核上，别裸跑满整机；kill 吃的是 PID，不是进程名，抄 PID 要抄准。

现象是改完配置 restart，mysvc 起不来，systemctl status 只报 failed，不说为什么。定位两步：先跑应用自检，python3 /opt/mysvc/mysvc.py --check，直接报出 mysvc.conf 第 2 行 unknown directive listen_prt；再用 journalctl -u mysvc -x 确认是同一个错。根因是我把 listen_port 少打了一个字母，配置解析不通过，服务在启动前就被拦下。修复：sed 改回来，再自检一遍，通过后才 restart。教训：status 给结果、自检给原因；改配置的标准动作是备份 → 改 → 自检 → 重启 → 验收。
